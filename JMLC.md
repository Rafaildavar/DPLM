# JMLC Research Track

## Идея

Текущая дипломная версия DPLM защищается как инженерный продукт: Flet GUI,
локальная конфигурация, БД, обучение жестов, KNN-распознавание, привязки команд,
самопроверка и журнал событий.

Для JMLC проект развивается как исследование качества распознавания:
рабочая система используется как стенд для A/B-тестирования моделей, признаков и
порогов уверенности. Цель — не просто заменить KNN, а показать полный цикл:

```text
сбор данных -> сравнение моделей -> анализ ошибок -> изменение алгоритма -> повторная проверка
```

## Гипотеза

Текущий `KNN + static_mean` теряет динамику жеста из-за усреднения последовательности
кадров в один вектор. Если добавить динамические признаки или модель, которая
работает с последовательностью, можно:

- поднять `confidenceThreshold`;
- снизить ложные срабатывания;
- лучше различать похожие динамические жесты;
- точнее настроить cooldown и пороги для опасных команд.

## A/B/C Варианты

| Вариант | Модель | Признаки | Роль |
|---|---|---|---|
| A | KNN | `static_mean` | Базовая дипломная версия |
| B | KNN / SVM / RF | `dynamic_stats` | Быстрый инженерный апгрейд |
| C | DTW-KNN | полная последовательность | Проверка динамических жестов |
| D | TCN / 1D CNN | последовательность кадров | Нейросетевой вариант при большем датасете |

## Метрики

- accuracy;
- precision / recall по каждому жесту;
- confusion matrix;
- false positive rate;
- false negative rate;
- средний confidence;
- recommended threshold;
- latency inference;
- live false trigger rate;
- количество ошибочных выполнений команды.

## План JMLC

1. Добавить `gesture_features.py` с режимами `static_mean` и `dynamic_stats`.
2. Расширить `train_classifier.py` параметрами `--features` и `--model-type`.
3. Реализовать benchmark-скрипт `scripts/compare_models.py`.
4. Сохранять отчёт сравнения в `docs/experiments/`.
5. Выбирать рекомендованный `confidenceThreshold` по результатам эксперимента.
6. Подтвердить результат live-тестом через журнал `recognition_logs`.

## Как это объяснять на защите

Диплом показывает готовую систему. JMLC показывает, что система стала
экспериментальной платформой: на ней можно измерять качество, менять модель,
подбирать пороги и доказывать улучшение метриками.

### Data Science

Текущую гипотезу стоит оформить как проверяемое исследование:

**Исследовательский вопрос:** достаточно ли статического усреднения ландмарков для пользовательских жестов, или динамические признаки снижают число ложных срабатываний без роста задержки?

**Данные:**

- источник: пользовательские записи из `data/gestures/`;
- единица наблюдения: один записанный жест как последовательность кадров;
- признаки: 21 ландмарк руки, координаты, количество рук, длина последовательности;
- риски данных: дисбаланс классов, разная длина жестов, освещение, положение руки, левша/правша, похожие жесты, отсутствие руки в кадре.

**EDA, который нужно добавить:**

- количество классов и семплов на класс;
- распределение длины записей в кадрах;
- доля кадров без уверенного детекта руки;
- разброс координат после нормализации;
- матрица расстояний между классами;
- визуализация похожих жестов и основных ошибок baseline.

**Предобработка:**

- нормализация относительно запястья;
- масштабирование по размеру ладони или bounding box;
- выравнивание длины последовательности;
- отдельная обработка одной и двух рук;
- динамические признаки: средняя скорость, ускорение, амплитуда, направление движения, статистики по временным окнам.

**Протокол экспериментов:**

- baseline: `KNN + static_mean`;
- B: `KNN / SVM / RF + dynamic_stats`;
- C: `DTW-KNN` на полной последовательности;
- D: `TCN / 1D CNN`, если будет достаточно данных;
- валидация: Stratified K-Fold для первичной оценки, отдельная live-сессия для проверки ложных срабатываний, при возможности Leave-One-Session-Out;
- метрики: macro F1, per-class precision/recall, confusion matrix, false trigger rate, latency, recommended threshold.

### Применение ИИ

В `JMLC.md` стоит явно разделить два уровня AI:

1. **AI внутри продукта:**
   - MediaPipe Hands как готовая CV-модель для ландмарков;
   - ML-классификатор пользовательских жестов;
   - голосовой помощник с STT/TTS как дополнительный канал управления.
2. **AI в процессе разработки:**
   - AI-агент для анализа литературы и выбора моделей;
   - AI-агент для генерации идей EDA и метрик;
   - AI-агент для code review и генерации тест-кейсов;
   - AI-агент для подготовки презентации и вопросов комиссии.

Чтобы это выглядело убедительно, нужно не просто сказать "использовал AI", а зафиксировать процесс:

- создать `docs/ai_usage.md`;
- для каждой задачи указать цель, инструмент, промпт или краткое описание запроса, полученный результат;
- отдельно написать, как результат проверялся вручную: тестами, экспериментами, чтением документации, запуском кода;
- подчеркнуть, что метрики моделей получены экспериментально, а не сгенерированы AI.

### Продуктовое мышление

**Проблема:** управление компьютером через клавиатуру, мышь и стандартные голосовые команды не всегда удобно: оно требует запоминания сочетаний клавиш, плохо персонализируется и не всегда подходит для сценариев, где руки заняты, нужна быстрая команда или важна доступность интерфейса.

**Целевая аудитория:**

- пользователи, которым нужны персональные быстрые команды без отдельного оборудования;
- разработчики, дизайнеры, монтажеры, стримеры и power users;
- пользователи с временными или постоянными ограничениями моторики;
- учебные и исследовательские сценарии HCI/CV.

**MVP:**

- запись собственных жестов;
- обучение модели на пользовательских семплах;
- привязка жеста к команде;
- live-распознавание через веб-камеру;
- настройка порога уверенности и cooldown;
- журнал срабатываний и ошибок.

**Конкуренты и альтернативы:**

- macOS Voice Control / Windows Voice Access - сильны в голосе, но не в жестовой персонализации;
- Stream Deck - надежен, но требует отдельного устройства;
- Leap Motion / Ultraleap - точный трекинг, но требует специального сенсора;
- готовые gesture-control приложения - часто ограничены фиксированным набором жестов.

**Дифференциация DPLM:**

- работает с обычной веб-камерой;
- жесты задает сам пользователь;
- команды настраиваются локально;
- данные и модели можно хранить локально;
- система измеряет качество и позволяет улучшать модель по метрикам.

**Продуктовые гипотезы:**

- пользователь может создать рабочий жест и привязать команду быстрее чем за 5 минут;
- динамические признаки уменьшают false trigger rate для похожих жестов;
- журнал ошибок помогает пользователю настроить порог без знания ML;
- локальная обработка повышает доверие к продукту.

**Импакт и метрики продукта:**

- time-to-first-command;
- процент успешно созданных жестов;
- false triggers per hour;
- среднее время выполнения команды;
- доля команд, выполненных без ручного исправления;
- SUS или UMUX-Lite после пользовательского теста.

### Мотивация

Мотивацию лучше связать с переходом от "просто работающего приложения" к исследуемой AI/ML-системе:

> Я хочу развиваться в AI/ML не только как пользователь готовых моделей, а как инженер, который умеет строить полный цикл: данные, признаки, обучение, валидация, продуктовая интеграция и эксплуатация. DPLM дает для этого практический стенд: компьютерное зрение, пользовательские данные, метрики качества, MLOps и реальный интерфейс. Магистерская программа нужна мне, чтобы углубить математическую базу ML, научиться ставить корректные эксперименты, работать с современными моделями последовательностей и доводить AI-решения до промышленного уровня.

В финальной версии нужно подставить название выбранной программы и 2-3 конкретных элемента ее учебного плана: курсы, лаборатории, исследовательские треки, проектную работу или индустриальных партнеров.

### Презентация и вопросы комиссии

Структура питча на 5-7 минут:

1. Проблема и аудитория: зачем нужен персональный gesture-control без спецоборудования.
2. MVP: показать запись жеста, привязку команды и live-распознавание.
3. Архитектура: GUI, CV, ML, БД, журнал событий, тесты.
4. Data Science: baseline, гипотеза про динамику, модели A/B/C/D, метрики.
5. Результаты: таблица качества, confusion matrix, latency, threshold, live false triggers.
6. Продукт: конкуренты, отличие, пользовательские гипотезы, обратная связь.
7. Развитие: MLOps, больше данных, последовательностные модели, accessibility-сценарии.

Ожидаемые вопросы и короткие ответы:

| Вопрос | Короткий ответ |
|---|---|
| Почему не сразу нейросеть? | Для малого персонального датасета KNN/SVM проще, быстрее и интерпретируемее. Нейросеть имеет смысл после накопления данных и проверки baseline. |
| В чем научная часть? | В проверке гипотезы о динамике жестов, сравнении признаков и моделей, подборе порогов и валидации live-ошибок. |
| Как защищаетесь от ложных срабатываний? | Порог уверенности, cooldown, per-class метрики, live false trigger rate и журнал `recognition_logs`. |
| Почему это продукт, а не демо? | Есть пользовательский сценарий: записать жест, обучить, привязать команду, пользоваться, видеть журнал и настраивать безопасность. |
| Как применялись готовые решения? | MediaPipe для ландмарков, scikit-learn/Optuna для ML, SQLAlchemy/Alembic для данных, Flet для GUI, pytest/Docker для инженерной воспроизводимости. |
