# Анализ предобработки данных и метрик жестов

## Где есть предобработка

Основная предобработка находится в `cv/train_classifier.py` внутри `load_dataset`:

- загрузка записанных `sample_*.npy` из `data/gestures/<gesture>/`;
- преобразование массива landmark-ов из `(T, D1, D2)` в `(T, D1 * D2)`;
- агрегация временной последовательности в один вектор через `mean(axis=0)`;
- приведение признаков к `float32`;
- выравнивание размерности признаков через zero-padding или обрезку;
- сохранение `classes.json` и `feature_dim.txt`, чтобы инференс использовал ту же размерность.

Нормализации координат относительно ладони, стандартизации признаков, фильтрации выбросов и аугментации в текущем пайплайне нет. Поэтому текущая модель сильно зависит от того, насколько одинаково пользователь держит руку, камеру и масштаб жеста при записи и инференсе.

## Как предобработка влияет на качество

Текущая предобработка критична для работоспособности KNN:

- flatten нужен, чтобы модель получила числовой вектор фиксированной длины;
- усреднение по времени снижает шум отдельных кадров, но теряет динамику жеста;
- padding/truncation предотвращает падения на разных форматах landmark-ов, но может скрывать несовместимые записи;
- отсутствие scale/pose normalization делает евклидово расстояние KNN чувствительным к масштабу, сдвигу и повороту руки.

На локальном датасете классы сейчас разделяются идеально даже без дополнительной нормализации. Это хороший знак для текущих записей, но не доказывает устойчивость в реальной камере: датасет маленький, содержит только два класса, а часть `.npy` файлов в локальном рабочем дереве зависает при чтении и была пропущена в воспроизводимом замере.

## Самые важные метрики

Для проекта распознавания жестов важнее всего:

1. `macro_f1` — главная метрика качества по классам, особенно когда классов станет больше или данных по ним будет разное количество.
2. `recall` по каждому жесту — показывает, насколько часто нужный жест вообще распознается.
3. `precision` по каждому жесту — показывает риск ложного срабатывания команды.
4. `confusion matrix` — нужна для понимания, какие жесты путаются между собой.
5. `latency` инференса — важна для пользовательского ощущения, хотя она не считается в текущем offline-скрипте.

Accuracy можно оставлять как общую справочную метрику, но при дисбалансе классов она менее надежна, чем macro-F1 и per-class recall/precision.

## Результат локального замера

Замер выполняется командой:

```bash
python scripts/evaluate_gesture_metrics.py
```

Скрипт использует тот же baseline feature pipeline, что и обучение: flatten, mean по времени, `float32`, выравнивание размерности. Дополнительно он сравнивает несколько вариантов нормализации поверх baseline.

Последний локальный результат сохранен в `docs/gesture_metrics_results.json`.

Краткая выжимка последнего запуска:

- прочитано 41 семпл из двух классов: `zoom` — 17, `zoom_one` — 24;
- 9 локальных `.npy` файлов были пропущены, потому что чтение/копирование зависало дольше `copy-timeout`;
- размерность признака после flatten и выравнивания — 84;
- baseline KNN, стандартизация, mean-centering и L2-нормализация дали одинаковый результат: `accuracy = 1.0`, `macro_f1 = 1.0`, `macro_precision = 1.0`, `macro_recall = 1.0`.

Интерпретация: на доступной части текущего локального датасета классы разделяются идеально, поэтому добавочная нормализация пока не меняет метрики. Практический риск остается в обобщении на новые условия камеры и руки, потому что датасет мал и состоит только из двух жестов.
