# Gesture Recording And Evaluation Protocol

Этот документ задает единый протокол записи и проверки жестов для ML-пайплайна
GestureBind. Цель: сделать датасет воспроизводимым, чтобы сравнение KNN, SVM,
ExtraTrees и других моделей было честным.

## Классы жестов

| Label | Тип | Текущий формат | Статус | Описание движения / позы |
|---|---|---|---|---|
| `CTRLZ` | static | `(30, 21, 2)` | usable | Статическая поза для команды undo. Визуальный шаблон нужно подтвердить перед финальным датасетом. |
| `Hend` | static / quasi-static | `(30, 21, 2)` | usable | Открытая ладонь / hand pose. Держать кисть неподвижно, без переноса руки по кадру. |
| `UP` | static | `(30, 21, 2)` | usable | Статическая поза "up". Не путать с dynamic-жестом `swipe_up`: здесь рука удерживается, а не двигается вверх. |
| `gun` | static | `(30, 21, 2)` | usable | Статическая поза "gun". Держать форму кисти без явного движения по кадру. |
| `sh3` | static / quasi-static | `(30, 21, 2)` | usable | Статическая поза из текущего набора. Нужна визуальная фиксация шаблона перед расширением датасета. |
| `three` | static | `(30, 21, 2)` | usable | Статическая поза "three". Держать кисть в одном месте, не делать свайп. |
| `hand_left` | dynamic | `(60, 21, 2)` | rerecord-required | Старый динамический жест. Нужно перезаписать в новом формате `(36, 44)`: старт справа/центр, движение всей руки влево, короткая фиксация в конце. |
| `swipe_up` | dynamic | `(36, 44)` | validated-live | Dynamic swipe вверх. Старт ниже центра кадра, движение всей руки вверх за 0.8-1.2 секунды, короткая фиксация сверху. |

## Типы жестов

### Static

Статический жест определяется формой кисти. Глобальное положение руки в кадре
не является основным сигналом.

Формат записи:
- `30` кадров;
- shape: `(30, 21, 2)`;
- `include_global_motion=False`;
- feature baseline: `static_mean`.

Правила записи:
- кисть полностью в кадре;
- держать позу стабильно весь сэмпл;
- не переносить руку по экрану;
- менять расстояние до камеры между сэмплами;
- менять небольшие углы кисти между сэмплами.

Ошибки записи:
- рука выходит из кадра;
- поза меняется внутри сэмпла;
- сильное движение руки;
- фон/свет мешают MediaPipe стабильно находить landmarks.

### Quasi-static

Квазистатический жест в основном задается позой, но допускает небольшое
естественное движение кисти. В текущем пайплайне он записывается как static,
пока не доказано, что нужен отдельный режим.

Формат записи:
- `30` кадров;
- shape: `(30, 21, 2)`;
- feature candidates: `static_mean`, `static_stats`.

Правила записи:
- поза должна быть узнаваемой на каждом кадре;
- допускается микродвижение, но не направленный swipe;
- не смешивать с dynamic-жестами.

### Dynamic

Динамический жест определяется траекторией движения. Для него обязательны
глобальные координаты запястья, потому что нормализация `wrist_scale` убирает
сам перенос руки по кадру.

Формат записи:
- `36` кадров;
- shape: `(36, 44)`;
- `42` признака нормализованной позы + `2` координаты запястья;
- `include_global_motion=True`;
- feature baseline: `dynamic_stats`;
- model candidates: `knn`, `svm`, `extra_trees`.

Правила записи:
- перед началом сэмпла занять стартовую позицию;
- выполнить движение всей рукой за 0.8-1.2 секунды;
- не менять радикально форму кисти во время движения, если жест не требует
  этого специально;
- после движения удержать финальную позицию 0.3-0.5 секунды;
- записывать вариативность: разные скорости, небольшие смещения, но одно и то
  же направление.

Ошибки записи:
- движение не в нужную сторону;
- движение слишком короткое;
- рука выходит из кадра;
- рука почти не двигается;
- жест выполняется только пальцами, а не переносом кисти/запястья.

## Dynamic Gesture Definitions

### `swipe_up`

Purpose: движение вверх.

Recording recipe:
- старт: ладонь ниже центра кадра;
- движение: вся рука вверх;
- конец: ладонь выше стартовой точки, короткая фиксация;
- ожидаемый знак движения: global `dy < 0`;
- минимальная целевая выборка: `30` сэмплов;
- рекомендуемая выборка для финала: `50-80` сэмплов.

Current dataset:
- samples: `30`;
- shape: `(36, 44)`;
- median global `dy`: about `-0.182`;
- live status: распознается корректно.

### `hand_left`

Purpose: движение влево.

Recording recipe:
- старт: ладонь справа от центра или в центре кадра;
- движение: вся рука влево;
- конец: ладонь левее стартовой точки, короткая фиксация;
- ожидаемый знак движения: global `dx < 0`;
- минимальная целевая выборка: `30` сэмплов;
- рекомендуемая выборка для финала: `50-80` сэмплов.

Current dataset:
- samples: `30`;
- shape: `(60, 21, 2)`;
- status: `rerecord-required`;
- причина: старые сэмплы не содержат global wrist motion и конфликтуют с
  новым `swipe_up`.

## Dataset Quality Gates

Перед обучением candidate-моделей проверить:

- каждый active class имеет не меньше `20` сэмплов;
- каждый dynamic class имеет shape `(36, 44)`;
- static и dynamic классы не смешаны в одном label;
- для dynamic-жестов median displacement выше static baseline;
- для directional dynamic-жестов global direction совпадает с описанием:
  - left: `dx < 0`;
  - right: `dx > 0`;
  - up: `dy < 0`;
  - down: `dy > 0`.

## Interface Recording Gate

Flet-запись должна помогать пользователю получать одинаковые сэмплы:

1. До записи каждого сэмпла рука должна быть найдена в кадре.
2. Стартовая поза должна быть стабильной несколько кадров.
3. После стабильной позы запускается короткий отсчет.
4. Если рука пропала во время записи, частичный сэмпл сбрасывается.
5. После сохранения в журнале обучения выводятся:
   - `motion` — среднее движение между кадрами;
   - `disp` — итоговое смещение последовательности;
   - `dx/dy` — глобальное смещение запястья для dynamic-формата `(36, 44)`;
   - `OK/WARN` — пригодность сэмпла для обучения.

Ожидаемые пороги для directional dynamic-жестов:

| Direction | Quality condition |
|---|---|
| left | `dx < -0.05` |
| right | `dx > 0.05` |
| up | `dy < -0.05` |
| down | `dy > 0.05` |

## Training Protocol

Для dynamic-кандидатов обучать одинаковый датасет в разные файлы:

| Model | Output |
|---|---|
| `knn` | `models/dynamic_knn.pkl` |
| `svm` | `models/dynamic_svm.pkl` |
| `extra_trees` | `models/dynamic_extra_trees.pkl` |

Общие параметры:
- data root: `data/gestures`;
- feature mode: `dynamic_stats`;
- classes metadata: `models/dynamic_classes.json`;
- feature dim metadata: `models/dynamic_feature_dim.txt`;
- feature mode metadata: `models/dynamic_feature_mode.txt`.

После обучения:
- запустить `scripts.compare_models --target-dim 44`;
- сохранить вывод в `docs/experiments/model_comparison.*`, если это финальный
  эксперимент;
- зафиксировать вывод в `ml_pipeline_log.md`.

Для каждого candidate model:

| Model | Gesture | Attempts | Correct | Missed | Wrong label | False positives | Median delay | Notes |
|---|---|---:|---:|---:|---:|---:|---|---|
| `dynamic_knn` | `swipe_up` | 10 |  |  |  |  |  |  |
| `dynamic_knn` | `hand_left` | 10 |  |  |  |  |  |  |
| `dynamic_svm` | `swipe_up` | 10 |  |  |  |  |  |  |
| `dynamic_svm` | `hand_left` | 10 |  |  |  |  |  |  |
| `dynamic_extra_trees` | `swipe_up` | 10 |  |  |  |  |  |  |
| `dynamic_extra_trees` | `hand_left` | 10 |  |  |  |  |  |  |

Правила live-теста:
- перед каждой попыткой убрать руку из кадра на 1 секунду;
- выполнить жест по recording recipe;
- считать `Correct`, если правильный label появился в поле жеста;
- считать `Missed`, если label не появился;
- считать `Wrong label`, если появился другой label;
- считать `False positives`, если label появляется без выполнения жеста;
- записывать субъективную задержку: `fast`, `ok`, `slow`.
